## minor_behavior_changes

**category**   : minor_behavior_changes  
**area**       : contrib  
**summary**    : [bp/1.39] contrib/istio: prefer app over app.kubernetes.io/name in workload metadata (#48384) (#48520)  
**commit**     : [4996e96242f7cd36585b84944c41296d06a457fa](https://github.com/envoyproxy/envoy/commit/4996e96242f7cd36585b84944c41296d06a457fa)  
**pr**         : [48384](https://github.com/envoyproxy/envoy/pull/48384)  
**description**:  
The Istio peer metadata conversion now takes a peer's app name and version from the ``app`` and ``version`` labels again, and uses ``app.kubernetes.io/name`` and ``app.kubernetes.io/version`` only when those labels are absent or empty. A workload's own stats always use ``app`` and ``version``, so giving the ``app.kubernetes.io/*`` labels precedence made ``source_app``, ``destination_app``, ``source_version`` and ``destination_version`` reported by a peer differ from the values the workload reports for itself, and the same workload showed up under two names. This restores the label precedence Istio proxies used before ``app.kubernetes.io/*`` labels were preferred.

**category**   : minor_behavior_changes  
**area**       : tls  
**summary**    : deps: distrust compromised eMudhra intermediate CAs (#48515) (#48528)  
**commit**     : [dfa3ff882b4a3eadd4d935b0f0107cc7f4b9a82e](https://github.com/envoyproxy/envoy/commit/dfa3ff882b4a3eadd4d935b0f0107cc7f4b9a82e)  
**pr**         : [48515](https://github.com/envoyproxy/envoy/pull/48515)  
**description**:  
Removed the ``AAA Certificate Services`` and ``emSign ECC Root CA - G3`` roots from the root certificate bundle built into Envoy Mobile. Both roots issued or cross-signed eMudhra intermediate CA certificates whose private keys were compromised (see https://emudhra.we-have-a-problem.com/). Servers whose certificate chains only lead to these roots are no longer trusted by Envoy Mobile when it uses its built-in bundle.
